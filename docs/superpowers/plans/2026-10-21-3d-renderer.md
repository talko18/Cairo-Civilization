# 3D Renderer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 2D canvas main map in `ui/index.html` with a three.js renderer that draws real terrain, distinct unit models, and every overlay the game needs.

**Architecture:** Two new sibling scripts beside `scenarios.js`. `render3d-core.js` holds pure logic with no three.js dependency — hex math, fog state, overlay lists, camera clamping — and is unit-tested in Node. `render3d.js` holds everything that touches the GPU and is verified by a headless-browser harness that asserts scene invariants and the draw-call budget. `index.html` keeps all game logic and DOM UI, loses `drawMap`/`drawUnit`, and drives the renderer through a small API.

**Tech Stack:** three.js r128 (cdnjs) + OrbitControls (jsDelivr), plain `<script>` tags, no build step. Tests: Node's built-in `node --test`, plus headless Chrome for the GPU half.

**Spec:** `docs/superpowers/specs/2026-10-21-3d-renderer-design.md`

> **One deliberate departure from the spec.** The spec's Constraints say the UI stays a single file. This plan puts the renderer in two sibling scripts instead, following the existing `scenarios.js` precedent. Reasons: logic embedded in `index.html` cannot be unit-tested at all, and `index.html` would reach roughly 7,000 lines. Everything else in the spec is followed as written. If the single-file constraint is preferred, both files can be inlined as `<script>` blocks — the cost is losing every Node test in Tasks 1–4.

## Global Constraints

- three.js **exactly** `https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js`, OrbitControls **exactly** `https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/controls/OrbitControls.js`. Both as plain `<script>` tags.
- No build step, no bundler, no new entry in `ui/package.json` `dependencies`.
- No network assets beyond those two scripts. All geometry generated in code.
- Do not modify `src/**`, `tests/**`, or `ui/server.js`. This is a rendering change only.
- Hex geometry is unchanged: flat-top hexes, odd-q offset coordinates, odd columns shifted **down**. Vertex 0 is due east; edge *i* runs from vertex *i* to vertex *(i+1) % 6*. River edge bitmasks from the contract depend on this exactly.
- Draw-call budget: under **~300** at normal play zoom, under **~800** worst case. If a change exceeds it, instance or merge something.
- Fog needs **both** ordering and filtering (Decision 12). Never bake fog into chunk vertex data (Decision 9).
- Full-screen flash: never stacks, has a cooldown, and does not run under `prefers-reduced-motion` (Decision 13).
- Labels are DOM elements over the canvas, never 3D text (Decision 5).
- Left-drag pans, right-drag rotates, arrows/WASD pan, panning clamped to map bounds (Decisions 6, 7).
- The minimap stays 2D (Decision 2). Only its viewport rectangle is rewired.

## Review Focus

- **Pointer outside the map.** Hover or click on empty ocean past the grid edge must select nothing, not crash. Pinned in Task 12.
- **A unit dies or a city is captured.** Its DOM label must be removed, not left orphaned on screen or leaked. Pinned in Task 11.
- **The right panel opens or closes.** `#map-area` changes width without a window resize; the renderer must follow. Today `openPanel`/`closePanel` do this via `setTimeout(resizeCanvas, 50)`. Pinned in Task 14.
- **A tile changes mid-game.** Improvement built, feature chopped, ownership flips. The owning chunk must rebuild and no other chunk may change. Pinned in Task 6.
- **WebGL is unavailable.** `init` must return false and the game must show a clear message rather than a blank canvas. Pinned in Task 5.

### Task 2: Terrain height and colour

**Files:**
- Modify: `ui/render3d-core.js`, `ui/test/core.test.js`

**Interfaces:**
- Consumes: Task 1's `hexCenter`, `hexCorner`, `neighbor`.
- Produces: `R3DCore.tileBase(tile) -> number`, `R3DCore.tileAmp(tile) -> number`, `R3DCore.heightAt(tile, x, z) -> number`, `R3DCore.colorAt(tile, x, z, h, tileLookup) -> {r,g,b}`, `R3DCore.subdivisions(tile) -> number`, `R3DCore.riverEdges(tile) -> [{edge, x1, z1, x2, z2}]`. `tile` is the existing `G.tiles` shape (`{q,r,terrain,feature,resource,improvement,riverEdges,...}`); `tileLookup(q,r)` returns a tile or null.

Terrain ids follow `TERRAIN_COLORS` at `index.html:520`: 0 ocean, 1 coast, 2/3 grassland, 4/5 plains, 6/7 desert, 8/9 tundra, 10/11 snow, 12 mountain; odd ids above 1 are hills.

- [ ] **Step 1: Write the failing tests**

```js
test('water sits below land and hills rise highest', () => {
  const ocean = {terrain: 0}, grass = {terrain: 2}, hills = {terrain: 3};
  assert.ok(C.tileBase(ocean) < C.tileBase(grass));
  assert.ok(C.tileAmp(hills) > C.tileAmp(grass));
});

test('heightAt returns exactly tileBase at every hex corner', () => {
  // the elevation falloff reaches zero at tile edges - the fog shell and the
  // chunk seams both depend on this
  const t = {terrain: 3, q: 4, r: 4};
  const c = C.hexCenter(4, 4);
  for (let i = 0; i < 6; i++) {
    const [dx, dz] = C.hexCorner(i);
    const h = C.heightAt(t, c.x + dx, c.z + dz);
    assert.ok(Math.abs(h - C.tileBase(t)) < 1e-6, `corner ${i} was ${h}`);
  }
});

test('a hill is higher at its centre than at its rim', () => {
  const t = {terrain: 3, q: 4, r: 4};
  const c = C.hexCenter(4, 4);
  assert.ok(C.heightAt(t, c.x, c.z) > C.heightAt(t, c.x + 0.9, c.z));
});

test('colorAt returns channels in 0..1', () => {
  const t = {terrain: 2, q: 1, r: 1};
  const c = C.hexCenter(1, 1);
  const col = C.colorAt(t, c.x, c.z, 0.25, () => null);
  for (const k of ['r', 'g', 'b']) {
    assert.ok(col[k] >= 0 && col[k] <= 1, `${k} out of range: ${col[k]}`);
  }
});

test('land next to water gets a beach tint', () => {
  const grass = {terrain: 2, q: 1, r: 1}, ocean = {terrain: 0, q: 2, r: 1};
  const c = C.hexCenter(1, 1);
  const lookup = (q, r) => (q === 2 && r === 1 ? ocean : null);
  const [dx, dz] = C.hexCorner(0);
  const edge = C.colorAt(grass, c.x + dx * 0.95, c.z + dz * 0.95, 0.25, lookup);
  const mid = C.colorAt(grass, c.x, c.z, 0.25, lookup);
  assert.ok(edge.r > mid.r, 'tile edge next to ocean should be sandier');
});

test('subdivisions are coarser for ocean than for hills', () => {
  assert.ok(C.subdivisions({terrain: 0}) < C.subdivisions({terrain: 3}));
});

test('riverEdges puts each bitmask bit on its own hex edge', () => {
  // the contract's 6-bit mask; bit i must land on edge i, which runs from
  // vertex i to vertex (i+1)%6. Getting this wrong rotates every river.
  const t = {terrain: 2, q: 4, r: 4, riverEdges: 0b000001};
  const segs = C.riverEdges(t);
  assert.strictEqual(segs.length, 1);
  assert.strictEqual(segs[0].edge, 0);
  const c = C.hexCenter(4, 4), [ax, az] = C.hexCorner(0), [bx, bz] = C.hexCorner(1);
  assert.ok(Math.abs(segs[0].x1 - (c.x + ax)) < 1e-9);
  assert.ok(Math.abs(segs[0].z1 - (c.z + az)) < 1e-9);
  assert.ok(Math.abs(segs[0].x2 - (c.x + bx)) < 1e-9);
  assert.ok(Math.abs(segs[0].z2 - (c.z + bz)) < 1e-9);
});

test('riverEdges returns one segment per set bit, none when clear', () => {
  assert.deepStrictEqual(C.riverEdges({q: 1, r: 1, riverEdges: 0}), []);
  assert.strictEqual(C.riverEdges({q: 1, r: 1, riverEdges: 0b101010}).length, 3);
  assert.deepStrictEqual(C.riverEdges({q: 1, r: 1, riverEdges: 0b010100})
    .map(s => s.edge), [2, 4]);
});
```
